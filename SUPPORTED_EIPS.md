# Supported Ethereum Standards Reference

This reference defines Wren's desktop support boundary. It is not an audit or
certification. It does not describe the separate browser extension. For method,
transport, permission, and origin behavior, see [RPC Compatibility](RPC_COMPATIBILITY.md).

## Status definitions

- **Implemented**: Wren owns the path and has automated regression coverage.
- **Partial**: Wren provides useful support with a material omission.
- **Review-only**: Wren recognizes and explains a format but does not provide its protocol or execution system.
- **Awareness-only**: Wren detects state but cannot change it.
- **Unsupported**: Wren has no maintained implementation.

These statuses describe usable Wren behavior, not internal groundwork. An
**Unsupported** row can mention a tested internal foundation. That mention does
not mean that accounts or applications can use the standard end to end.

## Provider and wallet interfaces

| Standard                                            | Status      | Wren behavior and limit                                                                                                                                                                                                                                                                                                                                                                                |
| --------------------------------------------------- | ----------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| [EIP-1193](https://eips.ethereum.org/EIPS/eip-1193) | Implemented | Provides `request`, `ProviderRpcError`, transition-only connection/account/chain events, subscription messages, and legacy compatibility methods. Account state updates before listeners. Local transport, embedded dapps, and the Companion have additional boundaries in [RPC Compatibility](RPC_COMPATIBILITY.md).                                                                                  |
| [EIP-1102](https://eips.ethereum.org/EIPS/eip-1102) | Implemented | Account exposure is permission-gated. `eth_requestAccounts` returns the selected account.                                                                                                                                                                                                                                                                                                              |
| [EIP-2255](https://eips.ethereum.org/EIPS/eip-2255) | Implemented | `wallet_getPermissions` and `wallet_requestPermissions` expose `eth_accounts`. Wren issues a 30-day capability scoped to the exact invoker, selected account, protected methods, and enabled-chain snapshot. It rechecks every standing and queued use. Direct browser-compatible origins remain assertions. Authenticated native and Companion credentials have separate revocable source identities. |
| [EIP-3085](https://eips.ethereum.org/EIPS/eip-3085) | Implemented | `wallet_addEthereumChain` validates bounded canonical IDs and metadata, accepts credential-free HTTPS RPC, explorer, and icon URLs, checks a supplied RPC's chain, and requires confirmation.                                                                                                                                                                                                          |
| [EIP-3326](https://eips.ethereum.org/EIPS/eip-3326) | Implemented | A known origin can switch its own route to a known enabled chain without approval or account exposure. Untouched old-route requests are cancelled; unknown origins and unknown or disabled chains fail closed.                                                                                                                                                                                         |
| [EIP-747](https://eips.ethereum.org/EIPS/eip-747)   | Implemented | `wallet_watchAsset` supports checksummed legacy ERC-20 and ERC-1046 ERC-20 suggestions. ERC-1046 is bounded to inline JSON or IPFS through Wren's gateway or Kubo endpoint, reconciled with contract reads, and validated. HTTP(S) metadata and images are rejected.                                                                                                                                   |
| [ERC-7811](https://eips.ethereum.org/EIPS/eip-7811) | Partial     | Parameterized `wallet_getAssets` returns chain-keyed native and ERC-20 balances for only the selected authorized account and granted chains. It supports explicit-asset, asset-type, and chain filters and advertises `assetDiscovery`; the existing no-parameter Wren response remains compatible. Wren does not index or claim ERC-721 or arbitrary asset types, and ERC-7811 remains Draft.         |
| [EIP-6963](https://eips.ethereum.org/EIPS/eip-6963) | Partial     | The embedded injector announces immutable EIP-1193 metadata and keeps the same legacy `window.ethereum` provider. Browser-wide discovery belongs to the separate Companion.                                                                                                                                                                                                                            |

## Signing and account intent

| Standard                                            | Status      | Wren behavior and limit                                                                                                                                                                                                                                                                       |
| --------------------------------------------------- | ----------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| [EIP-712](https://eips.ethereum.org/EIPS/eip-712)   | Implemented | Validates and reviews V3/V4 structured data, nested fields, and domain-chain risks. V1 arrays are separately identified as legacy compatibility, not EIP-712. Hardware capabilities differ.                                                                                                   |
| [EIP-2612](https://eips.ethereum.org/EIPS/eip-2612) | Review-only | Detects exact signed permits, including owner, spender, amount, expiry, nonce, chain, and contract. It does not implement permit contracts.                                                                                                                                                   |
| [Permit2](https://github.com/Uniswap/permit2)       | Review-only | Summarizes exact allowance, transfer, batch, and witness declarations without changing payloads. Explicit consent is required for authority, maximum amounts, and noncanonical contracts. It does not execute Permit2 or resolve token metadata.                                              |
| [ERC-3009](https://eips.ethereum.org/EIPS/eip-3009) | Review-only | Summarizes exact V4 transfer, receive, and cancellation authorizations. It enforces signer authorization and transfer consent. It does not execute ERC-3009 or infer token support.                                                                                                           |
| [ERC-4361](https://eips.ethereum.org/EIPS/eip-4361) | Review-only | Parses and reviews SIWE-shaped `personal_sign` messages and warns about origin, account, chain, time, and malformed data. It does not authenticate sessions or verify server nonces.                                                                                                          |
| [ERC-1271](https://eips.ethereum.org/EIPS/eip-1271) | Unsupported | Wren has a bounded configured-RPC `isValidSignature` verifier for a future pinned adapter, but no selectable contract account, signature-production adapter, or user-facing validation path. It does not infer Safe or other families from bytecode. See [Smart Accounts](SMART_ACCOUNTS.md). |
| [ERC-6492](https://eips.ethereum.org/EIPS/eip-6492) | Unsupported | Requires a pinned rollback-capable universal validator and the wrapper → ERC-1271/prepare → no-code-only EOA recovery order, using the selected adapter's exact factory payload and deployments. See [Smart Accounts](SMART_ACCOUNTS.md).                                                     |

Raw `eth_sign` remains available for compatibility. It is dangerous and
requires explicit risk consent. See [RPC Compatibility](RPC_COMPATIBILITY.md)
for the method boundary.

| [EIP-155](https://eips.ethereum.org/EIPS/eip-155)   | Implemented | Chain-binds legacy transactions before signing.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                        |
| [EIP-2718](https://eips.ethereum.org/EIPS/eip-2718) | Partial     | Handles legacy, type-1, and type-2 envelopes. It rejects explicit unsupported or unknown types rather than rewriting them.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                             |
| [EIP-2930](https://eips.ethereum.org/EIPS/eip-2930) | Implemented | Strictly validates, bounds, simulates, displays, and preserves ordered access lists. Trezor rejects type-1 because installed Connect has no request. Type-2 supports access lists.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                     |
| [EIP-1559](https://eips.ethereum.org/EIPS/eip-1559) | Implemented | Implements type-2 signing, exact quantities, fee-history estimation and editing, replacement fees, and safety checks. Speed Up and Cancel use the greater of current fees and the exact same-nonce replacement minimum, repeat configured-RPC receipt/nonce checks immediately before signing, and remain explicit reviewed transactions. Cancel is a competing zero-value self-transfer, not a guaranteed cancellation. Older hardware can use legacy fallback only without an access list.                                                                                                                                                                                                                                                                                                                                                                                                                           |
| [EIP-4844](https://eips.ethereum.org/EIPS/eip-4844) | Unsupported | Rejects type-3 and blob fields before approval. Complete support requires a KZG/trusted-setup and sidecar boundary, blob-fee accounting, chain activation policy, and signer/broadcast support. See [Advanced Execution](EXECUTION_BOUNDARIES.md).                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                     |
| [EIP-5792](https://eips.ethereum.org/EIPS/eip-5792) | Partial     | Supports `2.0.0` non-atomic `wallet_sendCalls`, status lookup and viewing, and conservative capabilities. Batches simulate and execute sequentially. Before accepting a batch, Wren repeats nonce, stateful simulation/account-code, pending-balance, aggregate value, worst-case execution-fee, and Optimism L1 data-fee checks. Insufficient funding retains the transient review for explicit chain-scoped funding, Reject, and Recheck actions without signing or broadcasting. Restart marks an unsigned empty admission failed because its private review payload is intentionally not persisted. A complete submitted batch resolves after every call has one canonical receipt, then resumes background reorg/finality checks after restart without rebroadcast. Atomic execution remains blocked on a pinned account-owned executor and is not advertised. See [Advanced Execution](EXECUTION_BOUNDARIES.md). |
| [EIP-7702](https://eips.ethereum.org/EIPS/eip-7702) | Partial     | Reads exact delegation indicators through the configured RPC and supports wallet-owned zero-address revocation for Ring and Seed accounts. It provides review, restart-safe evidence-only monitoring, reorg handling, and block-bound clearance evidence. Externally supplied type-4 or authorization input, creation or replacement without a pinned audited delegate, and hardware revocation remain unsupported. See [Advanced Execution](EXECUTION_BOUNDARIES.md).                                                                                                                                                                                                                                                                                                                                                                                                                                                 |
| [ERC-4337](https://eips.ethereum.org/EIPS/eip-4337) | Unsupported | No user operations, bundlers, EntryPoints, paymasters, or smart-account lifecycle. Wren requires a selected account family, controller model, chain deployments, bundler, and funding policy before implementation. See [Smart Accounts](SMART_ACCOUNTS.md).                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                           |

## Simulation evidence

Wren uses configured-RPC `eth_simulateV1` when available. Otherwise it uses
bounded `eth_call`. Successful single transactions can also request bounded
`debug_traceCall` prestate and optional call traces.

Wren can show native Wei deltas and summarized nested calls or creations. The
results can omit fees or details and remain RPC claims. Wren hides raw trace
input and return data. Standard token and NFT logs are reported effects, not
complete or independently verified balance changes. Stateful wallet-call
batches have no independent traces because a trace cannot represent state
between calls. Hardware evidence is in [Hardware Support](HARDWARE_SUPPORT.md).

EIP-7702 delegation and delegate-code checks are configured-RPC evidence, not
an audit. A call to a delegated recipient or target runs the first delegate's
code in that account's context. An ordinary outbound transaction from a
delegated sender does not automatically run its delegate.

## Chain-agnostic compatibility

| Standard                                                               | Status      | Wren behavior and limit                                                                                                                                                 |
| ---------------------------------------------------------------------- | ----------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| [CAIP-2](https://standards.chainagnostic.org/CAIPs/caip-2)             | Unsupported | Wren's removed historical envelopes no longer expose CAIP-2 routing. Use the top-level canonical hexadecimal EIP-1193 `chainId`.                                        |
| [CAIP-27](https://standards.chainagnostic.org/CAIPs/caip-27)           | Unsupported | Historical `caip_request` and `wallet_request` envelopes are removed and return `4200`. Wren does not implement current `wallet_invokeMethod` session or scope support. |
| [EIP-155 namespace](https://namespaces.chainagnostic.org/eip155/caip2) | Unsupported | Wren does not expose CAIP-2 namespace routing. EVM requests use a top-level canonical hexadecimal `chainId`.                                                            |
