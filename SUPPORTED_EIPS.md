# Supported Ethereum Standards

For developers who need Wren's exact desktop support boundary. This is not an audit, certification, or a claim about the separate browser extension.

**Implemented**: Wren owns the path and has automated regression coverage. **Partial**: useful support, with a material omission. **Review-only**: recognizes and explains a format but does not provide its protocol/execution system. **Awareness-only**: detects state but cannot change it. **Unsupported**: no maintained implementation.

These statuses describe usable Wren behavior, not internal groundwork. An `Unsupported` row may mention a tested internal foundation, but that is not a claim that accounts or applications can use the standard end to end.

## Provider and wallet interfaces

| Standard                                            | Status      | Wren behavior and limit                                                                                                                                                                                                                                                                                                              |
| --------------------------------------------------- | ----------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| [EIP-1193](https://eips.ethereum.org/EIPS/eip-1193) | Implemented | `request`, `ProviderRpcError`, transition-only connection/account/chain events, subscription messages, and legacy compatibility methods. Account state updates before listeners. Local transport, embedded dapps, and the companion have extra boundaries in [RPC Compatibility](RPC_COMPATIBILITY.md).                              |
| [EIP-1102](https://eips.ethereum.org/EIPS/eip-1102) | Implemented | Account exposure is permission-gated; `eth_requestAccounts` returns the selected account.                                                                                                                                                                                                                                            |
| [EIP-2255](https://eips.ethereum.org/EIPS/eip-2255) | Implemented | `wallet_getPermissions`/`wallet_requestPermissions` expose `eth_accounts`. Wren issues a 30-day capability scoped to the exact invoker, selected account, protected methods, and enabled-chain snapshot; every standing and queued use is rechecked. Direct localhost origins remain assertions rather than native-process identity. |
| [EIP-3085](https://eips.ethereum.org/EIPS/eip-3085) | Implemented | `wallet_addEthereumChain` validates bounded canonical IDs/metadata, accepts credential-free HTTPS RPC/explorer/icon URLs, checks a supplied RPC's chain, and requires confirmation.                                                                                                                                                  |
| [EIP-3326](https://eips.ethereum.org/EIPS/eip-3326) | Implemented | Switches a known enabled destination for only that origin, cancels untouched old-route requests, and returns `null`. Wren deliberately has no second confirmation after account access because routing is per-origin and review remains chain-bound.                                                                                 |
| [EIP-747](https://eips.ethereum.org/EIPS/eip-747)   | Implemented | `wallet_watchAsset` supports checksummed legacy ERC-20 and ERC-1046 ERC-20 suggestions. ERC-1046 is bounded to inline JSON or IPFS through Wren's gateway/Kubo endpoint, reconciled with contract reads, and validated; HTTP(S) metadata/images are rejected.                                                                        |
| [EIP-6963](https://eips.ethereum.org/EIPS/eip-6963) | Partial     | The embedded injector announces immutable EIP-1193 metadata and keeps the same legacy `window.ethereum` provider. Browser-wide discovery belongs to the separate Companion.                                                                                                                                                          |

## Signing and account intent

| Standard                                            | Status      | Wren behavior and limit                                                                                                                                                                                                                                                                       |
| --------------------------------------------------- | ----------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| [EIP-712](https://eips.ethereum.org/EIPS/eip-712)   | Implemented | Validates and reviews V3/V4 structured data, nested fields, and domain-chain risks. V1 arrays are separately identified legacy compatibility, not EIP-712. Hardware capabilities differ.                                                                                                      |
| [EIP-2612](https://eips.ethereum.org/EIPS/eip-2612) | Review-only | Detects exact signed permits, including owner, spender, amount, expiry, nonce, chain, and contract. It does not implement permit contracts.                                                                                                                                                   |
| [Permit2](https://github.com/Uniswap/permit2)       | Review-only | Summarizes exact allowance, transfer, batch, and witness declarations without changing payloads. Explicit consent is required for authority, maximum amounts, and noncanonical contracts. It does not execute Permit2 or resolve token metadata.                                              |
| [ERC-3009](https://eips.ethereum.org/EIPS/eip-3009) | Review-only | Summarizes exact V4 transfer, receive, and cancellation authorizations; enforces signer authorization and transfer consent. It does not execute ERC-3009 or infer token support.                                                                                                              |
| [ERC-4361](https://eips.ethereum.org/EIPS/eip-4361) | Review-only | Parses/reviews SIWE-shaped `personal_sign` messages and warns on origin, account, chain, time, and malformed data. It does not authenticate sessions or verify server nonces.                                                                                                                 |
| [ERC-1271](https://eips.ethereum.org/EIPS/eip-1271) | Unsupported | Wren has a bounded configured-RPC `isValidSignature` verifier for a future pinned adapter, but no selectable contract account, signature-production adapter, or user-facing validation path. It does not infer Safe or other families from bytecode. See [Smart Accounts](SMART_ACCOUNTS.md). |
| [ERC-6492](https://eips.ethereum.org/EIPS/eip-6492) | Unsupported | Requires a pinned rollback-capable universal validator and the wrapper → ERC-1271/prepare → no-code-only EOA recovery order, using the selected adapter's exact factory payload and deployments. See [Smart Accounts](SMART_ACCOUNTS.md).                                                     |

Raw `eth_sign` is available for compatibility but dangerous and requires explicit risk consent. See [RPC Compatibility](RPC_COMPATIBILITY.md) for methods.

## Transactions and execution

| Standard                                            | Status      | Wren behavior and limit                                                                                                                                                                                                                                                                                                                                                                     |
| --------------------------------------------------- | ----------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| [EIP-155](https://eips.ethereum.org/EIPS/eip-155)   | Implemented | Chain-binds legacy transactions before signing.                                                                                                                                                                                                                                                                                                                                             |
| [EIP-2718](https://eips.ethereum.org/EIPS/eip-2718) | Partial     | Handles legacy, type-1, and type-2 envelopes; rejects explicit unsupported/unknown types rather than rewriting them.                                                                                                                                                                                                                                                                        |
| [EIP-2930](https://eips.ethereum.org/EIPS/eip-2930) | Implemented | Strictly validates, bounds, simulates, displays, and preserves ordered access lists. Trezor rejects type-1 because installed Connect has no request; type-2 supports access lists.                                                                                                                                                                                                          |
| [EIP-1559](https://eips.ethereum.org/EIPS/eip-1559) | Implemented | Implements type-2 signing, exact quantities, fee-history estimation/editing, replacement fees, and safety checks. Older hardware can use legacy fallback only without an access list. Live speed-up/cancel needs broader client/L2 qualification.                                                                                                                                           |
| [EIP-4844](https://eips.ethereum.org/EIPS/eip-4844) | Unsupported | Rejects type-3 and blob fields before approval. Complete support requires a KZG/trusted-setup and sidecar boundary, blob-fee accounting, chain activation policy, and signer/broadcast support. See [Advanced Execution](EXECUTION_BOUNDARIES.md).                                                                                                                                          |
| [EIP-5792](https://eips.ethereum.org/EIPS/eip-5792) | Partial     | Supports `2.0.0` non-atomic `wallet_sendCalls`, status lookup/viewing, and conservative capabilities. Batches simulate and execute sequentially with crash-safe status; atomic execution remains blocked on a pinned account-owned executor and is not advertised. See [Advanced Execution](EXECUTION_BOUNDARIES.md).                                                                       |
| [EIP-7702](https://eips.ethereum.org/EIPS/eip-7702) | Partial     | Reads exact delegation indicators through the configured RPC and supports wallet-owned zero-address revocation for Ring/Seed accounts with review, rechecks, and clearance evidence. Externally supplied type-4/authorization input, creation/replacement without a pinned audited delegate, and hardware revocation remain unsupported. See [Advanced Execution](EXECUTION_BOUNDARIES.md). |
| [ERC-4337](https://eips.ethereum.org/EIPS/eip-4337) | Unsupported | No user operations, bundlers, EntryPoints, paymasters, or smart-account lifecycle. Wren requires a selected account family, controller model, chain deployments, bundler, and funding policy before implementation. See [Smart Accounts](SMART_ACCOUNTS.md).                                                                                                                                |

## Simulation evidence

Wren uses configured-RPC `eth_simulateV1` when available, otherwise bounded `eth_call`. Successful single transactions can also request bounded `debug_traceCall` prestate and optional call traces. It can show native Wei deltas and summarized nested calls/creations, but they can omit fees/details and remain RPC claims. It hides raw trace input/return data. Standard token/NFT logs are reported effects, not complete or independently verified balance changes. Stateful wallet-call batches have no independent traces because a trace cannot represent state between calls. Hardware evidence is in [HARDWARE_SUPPORT.md](HARDWARE_SUPPORT.md).

EIP-7702 delegation and delegate-code checks are configured-RPC evidence, not an audit. A call to a delegated recipient or target runs the first delegate's code in that account's context. An ordinary outbound transaction from a delegated sender does not automatically run its delegate.

## Chain-agnostic compatibility

| Standard                                                               | Status      | Wren behavior and limit                                                                                                                                      |
| ---------------------------------------------------------------------- | ----------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| [CAIP-2](https://standards.chainagnostic.org/CAIPs/caip-2)             | Partial     | Historical envelopes accept only canonical positive safely representable `eip155` references and map them to Wren routing. Other namespaces are unsupported. |
| [CAIP-27](https://standards.chainagnostic.org/CAIPs/caip-27)           | Unsupported | Wren has older permission-gated `caip_request`/`wallet_request` envelopes, not current `wallet_invokeMethod` session/scope support.                          |
| [EIP-155 namespace](https://namespaces.chainagnostic.org/eip155/caip2) | Partial     | Decimal references are limited to JavaScript's safe chain-ID range before canonical hexadecimal routing.                                                     |
