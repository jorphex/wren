# Wren 0.1.3

Wren 0.1.3 adds local wallet creation and contract tools. It also improves
transactions, browser connections, permissions, and restart recovery.

## New

- Create an encrypted local wallet with either a new 12-word recovery phrase or
  a new Ethereum private key. Wren uses the operating system's secure random
  generator, requires password confirmation, shows the secret once, checks the
  backup, and removes unfinished or expired setup data.
- Prepare contract deployments through Wren's ordinary simulation, review,
  signing, and single-broadcast path.
- Inspect and publish bounded Solidity/Vyper standard JSON or Foundry/Hardhat
  build-info for an existing contract or confirmed Wren deployment. Sourcify is
  primary. Etherscan V2 is an optional supported-chain fallback; its API key uses
  OS-protected storage, and constructor arguments must be supplied explicitly or
  confirmed absent. Published source becomes public and cannot be withdrawn
  through Wren.

## Improved

- Send now presents assets, contacts, search, networks, token icons, and balances
  consistently. Addresses and copy actions are clearer, and closing, retrying,
  queueing, replacement, submission, and monitoring states are more predictable.
- Transaction review stays attached to a submitted transaction instead of
  immediately returning to Requests. If the network does not confirm a
  submission, Wren keeps it visible for checking and does not send it again.
- Connected Apps now distinguishes current account access from global app
  activity. Per-account revocation uses an explicit consequence review, reliable
  focus recovery, and transient status feedback.
- Network editing has clearer endpoint status, failover information, and
  short-window layouts. Upgraded profiles repair Wren's recognized Companion
  connection so its network list remains available.
- Earn loads progressively, preserves public product context during partial
  failures, and applies the wallet privacy setting to every account-derived
  balance, amount, position, workflow, and receipt value.
- Generated-wallet, account-access, deployment, verification, network, Send, and
  signing surfaces have stronger keyboard, screen-reader, focus, scaling, and
  short-height behavior.

## Reliability and safety

- Upgrade tests start from an exact schema-68 Wren 0.1.2 profile and cover its
  move to the 0.1.3 schema, including encrypted signers, permissions, app
  identities, networks, contacts, tokens, and activity.
- Wren saves generated accounts and transaction intent before making them active
  or broadcasting. After a restart, it can distinguish work that never started
  from a submission whose result is still unknown, without sending twice.
- Access revocation and local-history clearing confirm that profile changes were
  saved before reporting success. If saving fails, Wren clearly says whether the
  change is temporary or uncertain.
- Before source publication, Wren saves the exact destination and request. It
  resumes status checks after restart without resubmitting an accepted request,
  and keeps the saved restart state bounded and free of secrets.
- Dapp chain switching can be approved before account access without silently
  widening account permission. Denial, revocation, expiry, and events remain
  limited to the requesting site and selected account.

Wren 0.1.3 is designed to pair with Wren Companion 0.1.2. Companion 0.1.2 adds
Chrome and Firefox identity switching, BaseScan/Etherscan connection
compatibility, tab-status summaries, and network-list recovery. The mutually
authenticated local protocol remains version 3.
