# Wren 0.1.12

Release candidate. Final builds and manual checks are pending.

This update adds token approval management and clearer signing reviews. It also
improves transaction previews, Lattice request preparation and balance reads.

## Changes

- Added **Approvals** below the account balance card. Check ERC-20 allowances and
  review a revocation from the list. It includes approvals sent through Wren and
  direct approvals found by Activity.
- Grouped signing reviews around the action, account, fee and permissions.
  Kept Sign visible, with required confirmations in a separate review.
  Raw signed fields and technical controls remain available.
- Added spender contract names and readable token amounts when matching metadata
  is available. Full contract addresses remain visible.
- Required new token-access consent when the reviewed request changes. Included
  unlimited token and NFT operator approvals in call batches.
- Added token-event previews from compatible RPC traces.
- Fixed Lattice transaction request preparation. Used local decoders for supported
  contract calls. Added support for flat Hyperliquid agent-approval messages.
  Rejected unsupported nested namespaced structs before signing.
- Reduced balance-request sizes and limited how many run at once. Preserved token edits and
  custom metadata during background reads.
- Aligned setup fields, dashboard controls, Earn actions and transaction progress.
  Kept private-key creation visible under Advanced.
- Ended pending Trezor requests when Wren closes the bridge.
- Updated Electron and reviewed dependencies. Removed unused code, fonts,
  artwork and build packages.

The Approvals list covers locally observed ERC-20 approval calls. It does not
include earlier approvals, NFT approvals or signed permits.

## Compatibility and checks

Browser pairing still uses protocol 3 with Companion 0.1.2 or 0.1.3.
Linux x64 remains the main release target. The Windows x64 preview is unsigned.
The macOS x64/arm64 previews use ad-hoc signatures and are not notarized.
See [signer support](../HARDWARE_SUPPORT.md) for test results and platform limits.

Automated checks pass on the development baseline. Final versioned builds,
package checks and physical-device results will be recorded in the
[0.1.12 preparation record](../QUALIFICATION.md#0112-preparation-record).
